Safety and privacy

Work in progress. This page describes the intended safeguards. Supervised accounts, public reporting, and hosted moderation are not live.

Mahanu is built around projects, not public personal profiles. There is no follower graph, direct-message network, behavioral advertising, or infinite feed. A project's workspace is private — like a family folder, not a social profile — and members are invited one by one.

What outsiders can see

Projects are private by default. A project can separately choose to:

  • show its name, tagline, and purpose in Explore; and
  • publish selected documents or media.

Neither choice publishes the member list or the rest of the project.

What Mahanu can see

Mahanu can read unencrypted project data stored on Mahanu servers. This access is used to operate the service and inspect hosted data for Code of Conduct enforcement.

At server creation or first server sync, an owner may also allow Mahanu to use unencrypted project data to create support material for that project and generic, anonymous templates, examples, research, and guidance. This is on by default, can be changed later, affects only future use, and never lets Mahanu edit the project. Generic material must not identify or link back to the source project or members.

Background commercial matching uses only public data. A signed-in adult may explicitly ask Mahanu to find sponsored support for a project. That request may use unpublished, unencrypted data the adult selects, but sponsors receive nothing unless an authorised adult submits an application. Passphrase-protected data is never used.

Protected files

A member may protect a supported small file with a passphrase entered on their device. Mahanu stores the encrypted file but cannot recover its passphrase or read its contents. Large protected files, protected media, protected metadata, search, and derived data are not supported initially.

Before creating one, show this warning:

Mahanu cannot read passphrase-protected files. By continuing, you agree that all project content, including protected files, follows Mahanu's Code of Conduct.

Members share the passphrase outside Mahanu. Losing it means Mahanu cannot recover the file. Concurrent protected-file edits become visible versions or branches, not a silent last-writer-wins overwrite.

Joining and removal

Account invitation, device pairing, project invitation, membership, and sync are separate steps. Pairing a laptop does not grant it a project.

Removing a member stops future project traffic after each project copy learns about the removal. It cannot recall readable files, encrypted files, passphrases, or keys already copied. Ordinary removal does not show a protected-file rotation warning. Manual rotation is available for a separately suspected passphrase or key compromise.

Children

The first family pilot uses guardian-operated devices and has no independent child account.

Supervised accounts are a later goal. Before release, Mahanu needs tested guardian consent, approved devices, account switching, recovery, membership control, public actions, reporting, deletion, age handling, and jurisdiction-specific legal review. The Guardian Addendum is a pre-launch draft, not a live promise.

Assistants and bots

An assistant is planned as an invoked helper. It may propose limited project changes and must wait for confirmation. It must not silently change membership, privacy, publishing, billing, or keys.

Bot accounts and conduct automation are future features. Their draft rules are in the Bot and Automation Policy. Mahanu does not claim that automation can replace human review or inspect passphrase-protected files.

Hard boundaries

Mahanu will not sell project or member data, run behavioral advertising, show commercial content to children, create public child profiles, or give sponsors access to unpublished project work or member identities.
