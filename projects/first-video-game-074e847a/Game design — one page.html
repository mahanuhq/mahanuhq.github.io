Game design — one page

The whole game on one page, written by the ten-year-old, in their words. Kept tiny on purpose — the number-one reason first games never get finished is that they got too big. If it doesn't fit on this page, it doesn't go in the first version.

The pitch (fill this in)

  • Why it's fun: (the feeling — beating your score, a satisfying pop, a scary chase)
  • You win when: _____ · You lose when: _____
  • Where it happens: (the world — one screen is plenty to start)

Scope rules (the hard part)

  • One core action, done well, before anything else.
  • One screen / one level for the first playable version.
  • No new idea gets added until the first version is finished and fun. New ideas go on the "later" list below, not into the game.

Build order

  1. Prototype — just the core action, ugly, but it feels good to do. (This is the make-or-break step.)
  2. Playtest — a friend or sibling plays without help; watch where they get stuck; fix that.
  3. Finish it — title screen, a "how to play", the win/lose, a restart button. The unglamorous 20%.
  4. Ship it — get it into a form other people can actually play.
